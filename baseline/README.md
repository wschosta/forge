# Reproducible baseline outputs

Matrix outputs for every configured state, generated by the current Python
pipeline under the committed TF-IDF classifier.

This directory is **not** committed — it is derived data that regenerates
deterministically. Rebuild it with:

```bash
forge classify                      # ~60s, trains +la/tfidf_classifier.pkl
./scripts/regenerate_baseline.sh    # ~15 min, all 11 configured states
```

## Why this exists

`data/{STATE}/outputs/` holds the MATLAB results of record. Those cannot be
reproduced by any amount of work: the classifier that generated them is not in
the repository and neither author has it. They are a historical reference, and
the golden test suite diffs against them — so they are never overwritten.

This tree is the reproducible counterpart: every file here can be regenerated
from committed inputs by the two commands above. Verified byte-identical across
repeated runs (matrix generation has no stochastic component; Monte Carlo and
Elo, which do, are not generated here).

## Agreement with the MATLAB outputs

Measured by `scripts/compare_baseline_to_matlab.py`, for the three states that
have committed MATLAB results:

| State | Pooled agreement matrix | Interpretation |
|-------|------------------------|----------------|
| **Oregon** | mean\|Δ\| = 0.0000 | exact, every file |
| **Wisconsin** | mean\|Δ\| = 0.0000 | exact, every file |
| Indiana | mean\|Δ\| = 0.0073 (H), 0.0009 (S) | moves |

Oregon and Wisconsin reproduce MATLAB exactly *under the new classifier*, which
is initially surprising. The reason is specific rather than lucky: the legacy
scorer left 36 Oregon and 25 Wisconsin bills unclassified, and none of those
bills had a competitive passage vote, so none of them was ever eligible for the
pooled matrix. The bill set is identical either way.

Indiana is the exception because 9 of its 142 previously-unclassified bills
*are* eligible, so the new classifier adds them. That, plus Indiana's
independently-documented provenance problems, accounts for its residual. Its
raw co-vote tallies differ by ~4 on average, which is the expected consequence
of nine additional bills rather than a numerical disagreement.

## Two states that are not fully covered

**Kentucky produces nothing.** `legiscan_data/KY/` contains no rollcall rows at
all, so there are no votes to build matrices from. This is a data gap, not a
code defect — the pipeline now warns rather than crashing.

**Maine is substantially incomplete.** Maine records passage through
parliamentary abbreviations — "Acc Maj OTP Rep" for accepting a majority
ought-to-pass report — which the passage-description pattern does not model.
Only 84 of its 2,514 rollcalls are recognised, yielding 31 House and 6 Senate
bills. That is enough to produce non-empty output, which makes the gap easy to
mistake for a small legislature.

Deciding which Maine motions constitute a passage vote is a domain judgement
about parliamentary procedure, not a pattern-matching exercise, so it is left
for the authors rather than guessed at. `tests/test_integration/
test_passage_vocabulary.py` pins the current state so the gap cannot be closed
by accident.
